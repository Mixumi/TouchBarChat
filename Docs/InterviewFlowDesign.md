# 面试回合与 Touch Bar 显示逻辑

本文件描述当前原生实现的决策边界，不把“识别到了文字”误当成“知道是谁说的”。输入仅为这台 Mac 播放的系统音频；Apple 本地 Speech 按每场面试固定的所选语言转写，SoundAnalysis 人声分类、PCM 声音活动与文字稳定性共同辅助判断问题是否结束。问句、指令及承接词线索随转写语言变化；AI 的回答语言可独立设置。`SpeechDetector` 当前不参与正式转写或终点判断。应用不采集麦克风，不做说话人识别，也不保存音频。

## 一次典型面试

1. 面试官通过会议软件提问。转写的局部结果持续替换当前题的文字快照；Touch Bar 从左侧人物图标后开始显示，并只保留最新两行。语音识别回改时以新快照重排，而不是把修正字句重复追加。启动时若只有无音频证据的孤立单字，先不展示；若识别器撤回临时文字，Touch Bar 同步清除。
2. 一个短暂停顿不直接结束问题。转写稳定、问题或指令特征、音频停顿和确认窗口共同决定是否提交候选题。通常等待约 1.6 秒 PCM 静音，明显未完句约 3 秒；文字至少稳定 0.7 秒，再确认 0.45 秒。没有新音频包时至少等待 2.2 秒，未完句按较长窗口兜底。SoundAnalysis 没检测到人声、低音量未触发 PCM 检测，或背景音乐使 PCM 一直非静音时，不永久卡住已转出的题目，而是延长到 3–6 秒的稳定文字窗口。Apple Speech 的“最终结果”只表示这段识别不再修正，不表示面试官已结束整道题。
3. 请求 AI 时，问题仍留在 Touch Bar。模型若认为话语明显没说完，可返回等待信号；应用保留转录继续观察。若同一问题随后又经过额外的安静确认，通常至少等待 5 秒无新声音，再自动发起一次无等待标记的回答；持续背景声下可结合 SoundAnalysis 的本机人声分类，等待窗口可能延长到 7 秒。新声音重计安静时间，新转写重新判断问题。持续无法确认时转为明确的手动入口，而非无限等待。模型返回第一段有效文字时才换成星光图标。
4. AI 的累计文字快照持续更新；每形成新的一行，两行窗口前进一步。点上箭头会锁住正在看的两行，后续输出仍接收并保存；点下箭头每次前进一步，追到最新后恢复自动跟随。完成时停在当前阅读位置，不定时翻页、不跳回开头。
5. 面试官追问时，不能仅凭 80 毫秒的声音能量取消旧回答；通知声、短暂附和都可能触发它。若新转写只是标点修正或“嗯”“好的”等短语，暂不切题；原题被修正或出现“以及／同时／包括”等补充条件，则把后半句合并到原题重新判断。出现可辨认的独立问题或至少六个有意义的新文字时，切回新转录；后者只表示“有新话语”，并非已确认新题，还要单独通过提问判断。网络请求代次与会话 ID 双重校验，使迟到的旧片段不能覆盖新题。
6. AI 已显示的部分回答会作为“生成中”记录，第一段立即落盘，之后合并写盘；完成、失败、面试结束或新题打断时立即保存最终状态。第一题回答过程中识别出的第二题前缀不会被第一题的完成事件吞掉。若第一题回答完成后才听到明确的补充条件，会把已给出的答案标为旧草稿，并对合并问题重新判断。没有返回任何有效片段时，记录为未完成，而不捏造回答；旧草稿也不会作为可靠的近期问答发给 AI。

## 必须区分的状态

| 状态 | Touch Bar 显示 | 新的系统音频／转写 | AI 片段 |
|---|---|---|---|
| 等待声音 | 人物图标＋等待提示 | 开始转录 | 无 |
| 转录当前题 | 人物图标＋最新两行 | 以最新识别快照修正 | 无 |
| 等待 AI 首段 | 仍显示当前题 | 实质修正则取消旧请求；短附和先观察 | 首段有效文字切换为 AI |
| AI 输出／回看 | 星光图标＋两行，上下按钮可用 | 确认新话语后切回人物图标 | 只有当前代次能更新显示与记录 |
| 暂停／结束 | 暂停提示／退出 Touch Bar | 暂停时等待最终识别，结束时取消未完成请求 | 未完成片段按状态保存 |

暂停排空期才识别完整的题目会保存为待处理；恢复后先留 1.6 秒给新语音继续，若文字未变、期间没有新的声音起始，再提交该题。暂停时未收到最终识别则只保存现有文字，不凭空补题。音频可能包含会议里的其他说话人、视频、通知或音乐。六字阈值只是减少短附和误打断的本地启发式，不是说话人识别，也不能保证每次恰好切题。菜单栏的“手动生成当前回答”可补救“团队规模”这类自动规则不敢判定的短追问，但 AI 正在生成时不可重复发起。完整原始转写保留供面试后核对。没有配置 API 时继续转写和记录，不生成回答；没有可用 Touch Bar 时，主窗口的记录仍可用。

## 应覆盖的回归场景

- 长问题中间停顿后追加“以及你承担的职责”、句末带“但是／比如”等未完提示，以及 Apple Speech 局部结果回改。
- AI 输出时出现“嗯”“好的”等短附和；它们不能因音量起伏立即抹掉回答。
- 第一题回答仍在输出或被用户回看时，第二题开始；第二题只显示自己的转录，旧网络片段失效。
- 短追问“为什么？”与没有问号的长句追问都能触发下一轮；不满足提问条件的长背景陈述仍可转录，但不应生成回答。手动入口需允许短隐含追问。
- 低音量转录、持续背景音乐、SoundAnalysis 分类滞后／不返回结果、采集停止发包、快速开启→结束→重开；辅助人声分类不可变成永久否决。
- API 返回“等待补充”后重新安静、通知音后重新安静、持续说话超过等待上限、正常 SSE、非流式 JSON 降级、超时／错误、用户暂停或结束；记录里的部分回答与状态不能伪装成完整答案。
- 问题末尾立即暂停，最终文字在排空期才出现；恢复后没有新音频也能处理保存的待答题，恢复后马上又说话则取消旧提交。
- 用真实可听见的会议播放测试多轮问答、Touch Bar 行宽、图标及按钮；自动测试通过不能代替实体设备验收。

## 参考与取舍

- [Apple Speech 的最终结果语义](https://developer.apple.com/documentation/speech/sfspeechrecognitionresult/isfinal)：识别结果稳定，不是整轮谈话结束。
- [Apple SpeechDetector 的 `results` 文档](https://developer.apple.com/documentation/speech/speechdetector/results)明确说明结果序列除错误外为空。本项目的合成中文语音测试得到 32 次非空转写更新、0 次 `speechDetected` 事件；检测器单独运行在本机发生框架级崩溃。[Apple 的模块说明](https://developer.apple.com/documentation/speech/speechdetector)还指出与转写器共用分析器会门控转写，可能降低准确率。因此当前原生程序不加载它、不把它当作实时终点信号，避免为尚不可用的检测结果牺牲转写完整性。
- [LiveKit 回合检测](https://docs.livekit.io/agents/logic/turns/turn-detector/)与[打断调优](https://docs.livekit.io/agents/logic/turns/tuning/)：把活动检测、回合结束和打断分开；短附和与真正抢话需要不同处理。
- [Pipecat 的用户回合策略](https://github.com/pipecat-ai/pipecat/blob/main/src/pipecat/turns/user_turn_strategies.py)和[Smart Turn](https://github.com/pipecat-ai/smart-turn)：VAD 可以触发进一步判断，但单靠静音不理解话语是否说完。

本项目继续优先使用 Apple 本地能力，没有把 LiveKit 或 Pipecat 的运行时/模型打包进 macOS 13 应用；以上是设计参考，不是已集成依赖。
