# TouchBarChat

[English](README.md)

TouchBarChat 是一款开源 macOS 面试记录与实时 AI 提示应用。它采集**这台 Mac 正在播放的声音**，使用 Apple 设备端语音能力转写；配置兼容 Chat Completions 的接口后，还可针对当前问题生成参考回答。Touch Bar 按阶段显示转录或回答；即使没有 Touch Bar，主窗口仍可保存、阅读、编辑和导出文字记录。

> **请在参与者知情且面试、会议或平台规则允许的前提下使用。** 本项目不判断某种使用方式是否合法或合规，也不用于绕过披露、监考或面试规则。它不能识别说话人，不能保证播放的声音一定来自面试官。

## 主要功能

- 使用 ScreenCaptureKit 采集电脑播放的音频，再由 Apple 本地语音识别转写；**不采集麦克风**，不读取屏幕画面，不保存音频或视频。
- Touch Bar 用两行滚动窗口分别展示实时转录与 AI 回答。回答阶段可用轻量的上／下按钮，或 `Control + Option + ←/→`，回看尚未读完的文字；转录阶段不提供翻页。
- 使用本机声音活动、Apple SoundAnalysis、文字稳定性和问题特征判断何时提问 AI。若自动判断等待过久，可从菜单栏手动生成当前回答。
- 回答流式显示并逐段写入本机记录。遇到追问、API 错误或结束面试时，已有的部分回答会保留，并标记未完成。
- 面试进行中自动保存文字；结束后可编辑整篇 Markdown、恢复自动整理的版本、删除记录或导出 `.md` 文件。
- 提供首次使用引导、权限检查、菜单栏操作，以及跟随系统／浅色／深色外观。跳过 API 配置仍可转写并保存记录。

问答结束、补问、打断和迟到回答的具体处理见[面试流程设计](Docs/InterviewFlowDesign.md)及[实时链路说明](Docs/InterviewRuntime.md)。

## 系统要求与验证范围

| 项目 | 要求或现状 |
| --- | --- |
| macOS | Swift 包声明最低 macOS 13。开发与自动测试在 macOS 26.7 上运行过；这不等于打包后的应用已在 macOS 13–25 或其他机型验证，仍需分别实机测试。 |
| 开发工具 | Xcode 或 Apple Command Line Tools，需支持 Swift 6。 |
| 本地转写 | 所选语言必须在本机获得 Apple 设备端语音识别支持。macOS 26 优先使用 SpeechAnalyzer／SpeechTranscriber；旧版本或不支持新版路径时使用只允许本地识别的 SFSpeechRecognizer。首次使用可能下载 Apple 模型；不会悄悄切换成云端转写。 |
| Touch Bar | 可选。没有 Touch Bar 时主窗口记录仍可用。Touch Bar 展示依赖未公开的 AppKit 接口，未来 macOS 版本可能不兼容。 |
| AI 回答 | 可选。需要用户自行提供兼容接口；网络、费用、服务商数据留存和模型输出质量不由本项目保证。 |

### 多语言如何工作

项目提供简体中文、英语、韩语、日语、俄语、法语和巴西葡萄牙语的界面翻译资源。在“**设置 → 语言**”中，可以让界面跟随 macOS 首选语言，也可以明确选择这七种语言之一。翻译未覆盖的文字目前可能回退为简体中文。

“**面试官使用的语言**”与“**AI 回答语言**”是两项独立设置。可选面试语言为 `zh-CN`、`en-US`、`ko-KR`、`ja-JP`、`ru-RU`、`fr-FR`、`pt-BR`；回答可跟随面试语言，也可单独选择。列出语言选项**不代表**对应的 Apple 本地模型在每台 Mac 上都已安装、受支持或经过本项目实机验证。开始采集前会检查所选语言的本地能力；AI 回答语言只是向所配模型提出的要求，不能保证模型一定遵守。

| 层次 | 语言规则 |
| --- | --- |
| 界面 | 七种语言资源；默认跟随 macOS，也可在设置中手动选择；缺失翻译回退为简体中文。 |
| 转写 | 使用指定的面试语言，且仅在当前 Mac 支持该语言的设备端识别时启动；不将音频发送给远程识别服务。 |
| AI 回答 | 已配置 API 时使用指定的回答语言；默认跟随面试语言。 |
| 历史记录 | Markdown 标签与面试语言一起保存，之后更改界面语言不会重写旧记录的标签。 |

## 从源码构建

在仓库根目录执行：

```bash
./Scripts/check.sh
./Scripts/build-app.sh
open Build/TouchBarChat.app
```

检查脚本会运行严格的 Swift 格式检查和测试套件；这些检查不能代替七种语言的实机转写或 Touch Bar 硬件验证。

构建脚本输出 `Build/TouchBarChat.app`，**默认使用临时签名**，不会自动读取或选择本机的开发者签名身份。如需使用 Apple Development 身份，必须显式指定：

```bash
TOUCHBARCHAT_SIGN_IDENTITY="Apple Development: Your Name (TEAMID)" ./Scripts/build-app.sh
```

上面的签名名称只是占位示例，不是项目凭据。请勿提交证书、描述文件、API Key、面试记录或本机签名的构建产物。默认的临时签名在重新构建后可能使 macOS 要求重新授权；本地测试时保持应用路径和显式开发者签名身份稳定有助于减少这种情况。应用标识为 `dev.touchbarchat.app`。

## 首次设置和使用

1. 打开应用，依次完成“**权限 → AI 接口 → 回答偏好 → 欢迎**”引导。选择面试官使用的语言，授予“**屏幕与系统音频录制**”。旧版语音识别路径还可能要求“**语音识别**”权限；macOS 26 上受支持的 SpeechTranscriber 路径无需该权限。
2. 如需 AI 回答，填写服务商的**完整 Chat Completions URL**、准确的模型名、API Key 和个人背景。远程地址必须使用 HTTPS；只有本机回环地址允许 HTTP。远程 API 必须提供 Key，本机回环接口可以不填。暂时不需要 AI 时可跳过。
3. 点击主窗口右上角的开始图标。程序先检查权限、本地语音能力及已填写的 API 设置，再开始采集并最小化窗口。
4. 面试过程中，用菜单栏图标暂停、继续、结束、手动生成当前回答或重新打开主窗口。这时记录只读；结束面试后再编辑、删除或导出。

Touch Bar 左侧的**人物图标**代表面试官语音转录，**星光图标**代表 AI 回答。文字是连续更新的两行窗口，不是按翻页速度逐字输出；回答阶段的上下操作只改变阅读位置，不丢弃新到达的内容。

## 数据、权限和隐私

| 数据 | 去向 |
| --- | --- |
| 电脑播放的声音 | ScreenCaptureKit 只为采集系统音频建立流，不注册画面输出；Apple 本机语音与声音分析处理音频。应用不请求麦克风，不保存音频，不把音频发送到所配置的 AI 接口。首次下载 Apple 本地语音模型可能需要联网。 |
| 面试文字 | 默认保存在 `~/Library/Application Support/TouchBarChat/interviews.json`。这是**本机未加密的文字文件**，不是保密保险箱。应用不会自动上传到 GitHub；导出的 Markdown 保存到你选择的位置。 |
| API 配置 | API Key 存在 macOS 钥匙串；接口地址、模型名和个人背景存在本机用户设置中，而非源码中。 |
| AI 请求 | 启用 AI 时，所选接口会收到当前问题、个人背景以及最多三组近期问答草稿；填写了 Key 时通过 Bearer 凭据发送。服务商可能按照自己的条款处理或留存这些文字。 |

使用前请确认面试规则与 API 服务商隐私政策。提交截图、日志、问题报告或代码时，也请先去除真实姓名、个人资料、密钥和面试内容。

## 优点与局限

本项目优先采用 Apple 本地转写、只保存文字、无需 API 即可记录，并让 Touch Bar 成为不必频繁切换窗口的阅读入口；没有 Touch Bar 也能使用主窗口记录。

同时应了解：

- 它采集的是符合系统过滤条件的**电脑播放声音**，可能包括会议参与者、视频、音乐或通知；不会采集你对麦克风说的话，也无法分辨说话人。
- 本地识别的可用语言与质量取决于 Apple 模型、设备、系统版本和音频条件；临时转写会被修订，也可能漏字。
- 判断问题是否结束、是否出现追问属于启发式推断，不保证每次时机都正确。`SpeechDetector` 暂未作为结束信号，原因和实测见[设计文档](Docs/InterviewFlowDesign.md#参考与取舍)。
- AI 回答可能延迟、错误、不完整，或与用户真实经历不符；只能作为参考，不能当作已核实事实。
- Touch Bar 使用未公开 AppKit 接口，未来兼容性不确定，也不适合当前方式直接进入 Mac App Store；这里没有提供公证过的发行版。
- 本地记录没有加密；启用 AI 后，文本会送到你选择的服务商。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 系统权限列表没有 TouchBarChat | 先在应用内请求权限，再打开 macOS 隐私设置。系统要求重启时，退出并重新打开**同一签名的应用**；测试期间不要替换为不同签名的构建。 |
| 显示“正在识别”但没有文字 | 确认声音是从这台 Mac 的会议软件或浏览器播放，而不是只对着麦克风讲话；检查面试语言和该语言的本地语音模型。 |
| 转写慢或漏字 | 检查会议播放音量、选定语言与音质。临时结果会回改，最终结果可能较晚到达；反馈问题时只提供虚构或经同意的短句。 |
| 没有 AI 回答 | 检查 API 设置是否完整、URL 是否为完整 Chat Completions 地址、服务商是否支持所填模型；自动判断等待过久时可试菜单栏“手动生成当前回答”。 |
| Touch Bar 不显示 | 确认机器有可用的 Touch Bar；未来系统也可能不再提供所需接口。主窗口记录是降级路径。`swift run TouchBarChat --probe` 只检查私有 selector 是否存在，不会启动面试。 |
| 重新构建后权限失效 | 尽量保持固定的应用标识、路径和签名身份；临时签名不保证保留 TCC 授权。 |

在仓库根目录运行 `./Scripts/check.sh`，即可执行严格格式检查与测试。自动测试涵盖设置校验、文字持久化、问答边界、AI 流式响应和 Touch Bar 翻页等，但不能证明七种语言都已在实体设备完成转写验收，也不能代替参与者知情情况下的采集测试。贡献规范见 [CONTRIBUTING.md](CONTRIBUTING.md)，设计参考和第三方声明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)；当前 Swift 包不链接第三方库。
